システム全体構成

1. この文書で決めること

経費精算システムを構成する主要な要素と各要素の役割、代表的な処理の流れを定義する。 詳細な処理、状態遷移、例外は ../detailed/01-application-design.md で定義する。

構成を決める入力として、FR-001からFR-004、IF-001からIF-004、 NFR-001、NFR-002、NFR-007、CON-002を参照する。

2. システム全体図

申請者・承認者・経理担当者
              ↓
       経費精算システム
       ├─ 社内認証基盤
       ├─ 人事システム
       ├─ メール配信サービス
       └─ 会計システム

利用者はWebブラウザから経費精算システムを利用する。外部システムとの具体的な 情報、タイミング、方式は要件定義の06-related-systems-and-integrations.mdを正本とする。

3. 構成要素と役割

構成要素 役割 関連要件
Web UI 申請、承認、経理確認の操作を提供する FR-001、FR-003
アプリケーションAPI 業務ルール、権限、状態遷移を管理する FR-001からFR-004
非同期ジョブ 組織情報取込、通知、CSV生成を実行する IF-002からIF-004
データストア 申請、状態、操作履歴を保存する DR-001
証憑ストレージ 領収書画像を保存する DR-001

4. 代表的な処理の流れ

  1. 申請者がWeb UIから申請を提出する。
  2. アプリケーションAPIが入力、権限、状態を確認する。
  3. 申請データと操作履歴をデータストアへ保存する。
  4. 非同期ジョブへ承認者通知を登録する。
  5. 非同期ジョブがメール配信サービスへ通知を依頼する。

5. 設計上の判断と未確定事項

5.1 設計上の判断

  • ADR-001: 単一の配備単位の中を申請、承認、連携、監査のモジュールに分割する。
  • DEC-001: 会計システムとの初回連携にはCSVを使用する。

5.2 未確定事項

  • ISSUE-022: 非同期ジョブの同時実行数
  • ISSUE-023: 証憑ストレージの暗号鍵管理方式
