```markdown
# ADR-001 アプリケーションの分割方式

## 状態
accepted

## 背景
申請、承認、連携を分離しつつ、初回リリースの規模と運用体制に合う構成を選ぶ必要がある。

## 判断
単一の配備単位の中を申請、承認、連携、監査のモジュールに分割する。

## 比較した選択肢
- 単一アプリケーションをモジュール分割する。
- 機能ごとに独立サービスへ分割する。
- 分割しない単一構造とする。

## 判断理由
独立サービスの運用負荷を避けながら、責務境界と将来の分離可能性を確保できるため。

## 利点
- 配備と障害対応の対象が少ない。
- 業務トランザクションを一つのデータストアで扱える。

## 欠点・影響
- 一部機能だけを独立して拡張できない。
- モジュール境界をコードレビューで維持する必要がある。

## 関連する要件・制約
FR-001からFR-004、NFR-001、NFR-002、運用体制上の制約。

## 再検討条件
特定モジュールの負荷またはリリース頻度が他のモジュールから独立して増加した場合に再検討する。
```
