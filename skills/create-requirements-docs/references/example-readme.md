# 経費精算システム 要件定義

## 文書の目的

本書群は、経費精算システムの開発範囲、業務要求、システム要件、
品質条件および受入条件について、業務部門と開発チームが合意するために作成する。

## 対象プロジェクト

Excelと紙で運用している国内経費の申請、上長承認、経理確認をWebシステムへ移行する。

## 想定読者

- プロジェクト責任者
- 経理部門と情報システム部門
- 開発、テスト、運用担当者
- 内部監査担当者

## 文書一覧

必須性は次の3段階で示す。

- 必須: 原則としてすべての案件で作成する。
- 条件付き: 記載対象が存在する場合に作成する。
- 任意: 意思決定や利用者理解に役立つ場合に作成する。

### ビジネスと利用者を理解する文書

| 文書 | 内容 | 必須性 | ステータス | 責任者 |
|---|---|---|---|---|
| 01-business-overview.md | 背景、課題、目的、成功指標 | 必須 | approved | 経理部責任者 |
| 02-targets-and-personas.md | 対象顧客、対象利用者、典型的な利用者像 | 任意 | draft | 業務分析担当者 |
| 03-stakeholders.md | 関係者、利用者、プロジェクトとの影響関係 | 必須 | approved | プロジェクト責任者 |

| 05-business-process-before-and-after.md | 現行業務、将来業務、変更点、業務ルール | 条件付き | in-review | 業務分析担当者 |

### システムに求める内容を定義する文書

条件付き・任意文書は、READMEに記載した作成条件へ該当するときに作成する。

## 推奨する閲覧順序

初回は `requirements/` 直下の文書を番号順に読む。
個別要件の確認時は、要件IDと相対リンクから上位要求と受入条件をたどる。

## 要件IDの規則

| 種別 | プレフィックス | 例 |
|---|---|---|
| ビジネス目的 | BO | BO-001 |
| ペルソナ | PER | PER-001 |
| 業務フロー | BP | BP-001 |
| 業務ルール | BR | BR-001 |
| 機能要件 | FR | FR-001 |
| データ要件 | DR | DR-001 |
| システム連携要件 | IF | IF-001 |
| 非機能要件 | NFR | NFR-001 |
| 受入条件 | AC | AC-001 |

## 更新・レビュー方法

文書責任者が変更案を作成し、影響する要件と受入条件を更新する。
Must要件の追加・変更は、プロジェクト責任者と業務責任者の承認を必要とする。
