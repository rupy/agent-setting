# 記述の悪い例と改善例

曖昧さ、複数要求の混在、実装方法の早すぎる固定、根拠のない数値を避けるために参照する。

## 悪い例と改善例

### 曖昧な性能要件

悪い例: `画面を高速に表示できること。`

改善例: `同時利用者100名以下で、通常画面のリクエストの95%が2秒以内に完了すること。領収書アップロードは測定対象外とする。`

### 複数要求の混在

悪い例: `利用者は申請を登録、承認、削除でき、管理者には通知されること。`

改善方法: 登録、承認、削除、通知を別々の要件IDに分割し、それぞれの利用者、権限、例外、受入条件を記載する。

### 実装方法の早すぎる固定

悪い例: `ReactとPostgreSQLを使用して申請画面を実装すること。`

改善例: `申請者は会社がサポートするWebブラウザから経費申請を登録できること。`

特定技術が必須なら、機能要件ではなく根拠付きの技術制約として記録する。

### 根拠のない数値

悪い例: `申請データを10年間保存すること。`

保存期間を確認できていない場合は、もっともらしい値を入れず、担当者、期限、影響、確認先を持つ未確定事項として記録する。
