# 前提条件と制約

## 前提条件

### ASM-001 社内アカウントの保有

- 内容: 対象となる全従業員が社内認証基盤のアカウントを持つ。
- 根拠: 情報システム部へのヒアリング結果
- 確認方法: 対象雇用区分とアカウント発行規則を照合する。
- 前提が崩れた場合の影響: 別の認証またはアカウント管理機能が必要になる。

## ビジネス上の制約

### CON-001 現行経費規程の維持

- 内容: 初回リリースでは承認権限と精算可能な経費区分を変更しない。
- 根拠: 規程改定を本プロジェクトの対象外としたため。
- 影響: 現行規程の手作業判断の一部が残る。

## 技術上の制約

### CON-002 既存認証基盤の利用

- 内容: 認証には既存のOpenID Connect対応基盤を使用する。
- 根拠: 全社セキュリティ方針
- 影響: 認証基盤の停止時は新規ログインできない。

## 法令・契約上の制約

証憑の保存方式と期間は適用法令、社内規程、クラウド契約のデータ保管条件を満たす必要がある。
詳細はISSUE-001の確認結果に従う。

## スケジュール・予算上の制約

初回リリースは2027年4月1日までとし、会計APIの追加契約費用は予算に含まない。
この制約により初回はDEC-001のCSV方式を採用する。
