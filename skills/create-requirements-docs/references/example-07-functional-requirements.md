# 機能要件

## 1. 機能要件の記述規則

要件IDはFRから始め、一つのIDに一つの検証可能な振る舞いを記載する。
Must要件には上位要求と受入条件を対応させる。

## 2. 機能一覧

| ID | 機能 | 優先度 | 上位要求 | 受入条件 |
|---|---|---|---|---|
| FR-001 | 経費申請の提出 | Must | BP-001 | AC-001、AC-002 |
| FR-002 | 申請状況の参照 | Must | BO-002、BP-001 | AC-003 |
| FR-003 | 申請の承認・差し戻し | Must | BP-001 | AC-004 |
| FR-004 | 会計連携用CSVの出力 | Should | BO-001 | AC-005 |

## 3. 個別機能要件

### FR-001 経費申請の提出

- 概要: 下書きの経費申請を承認者へ提出できること。
- 根拠: 紙による申請をオンラインへ移行するため。
- 対象利用者: 申請者
- 利用者が実現したいこと: 支払い後に経費情報と領収書を提出する。
- 関連するスコープ: 経費申請、領収書
- 関連する業務フロー: BP-001
- 事前条件: 申請者がログインし、申請が下書き状態である。
- トリガー: 申請者が提出を実行する。
- 入力: 支払日、金額、経費区分、支払先、利用目的、領収書画像
- 基本処理:
  1. 必須項目と入力形式を検証する。
  2. 組織情報から承認者を決定する。
  3. 状態を上長承認待ちへ変更する。
  4. 承認者へ通知する。
- 出力: 提出結果、申請番号、現在の状態
- 事後条件: 承認者が承認待ち一覧から申請を確認できる。
- 例外: 入力不足または承認者未設定の場合は提出せず、理由を表示する。
- 権限制御: 申請の所有者だけが提出できる。
- 優先度: Must
- 上位要求: BO-001、BO-002、BP-001
- 受入条件: AC-001、AC-002

## 4. 認証・認可

- 社内認証基盤で認証された利用者だけが利用できる。
- 申請者は自分の申請、承認者は割り当てられた申請を閲覧できる。
- 経理担当者は上長承認済みの申請を閲覧・処理できる。
- システム管理者権限だけでは申請内容を閲覧できない。

## 5. 監査・履歴

申請提出、承認、差し戻し、経理承認、CSV出力、権限変更について、
実行者、対象、日時、変更前後の状態、結果を記録する。利用者は履歴を変更できない。

## 6. エラー処理

- 入力エラーは対象項目と修正方法を表示する。
- 一時的な外部連携エラーでは入力済み内容を失わせない。
- 内部情報やスタックトレースを利用者へ表示しない。
- 業務継続に影響するエラーは監視対象として運用担当者へ通知する。
