# 開発計画

## 1. 開発の進め方

開発を、基盤準備、主要機能、外部連携、受入・移行の4フェーズに分ける。
各フェーズは完了条件を満たした時点で完了とし、独立して実施できる作業は並行して進める。

## 2. 開発フェーズ

| フェーズ | 目的 | 主な対象 | 対象要件 | 成果 |
|---|---|---|---|---|
| 1. 基盤準備 | 開発・検証の土台を整える | 環境、認証、基本データ | IF-001、CON-002 | 検証環境へログインできる |
| 2. 主要機能 | 基本業務を実現する | 申請、承認、差し戻し | FR-001〜FR-003、DR-001 | 基本業務フローを実行できる |
| 3. 外部連携 | 関連システムと接続する | 組織取込、通知、会計連携 | IF-002〜IF-004、FR-004 | 連携試験を実行できる |
| 4. 受入・移行 | 本番利用の準備を整える | 受入試験、移行、運用準備 | AC-001、AC-002、AC-003、AC-004、AC-005、AC-010、NFR-007 | 利用開始を判断できる |

## 3. フェーズ間の依存関係

- 主要機能の結合試験には、認証と基本データの準備が必要である。
- 会計連携の試験には、承認済み申請を作成できる必要がある。
- 受入試験には、Must要件と利用開始に必要な外部連携が実装済みである必要がある。
- 運用準備と操作手順の作成は、主要画面が安定した段階から並行して進める。

## 4. 各フェーズの完了条件

| フェーズ | 完了条件 |
|---|---|
| 基盤準備 | 対象利用者が検証環境へログインでき、監視で稼働を確認できる |
| 主要機能 | 申請から経理承認までの基本フローと主要な例外を実行できる |
| 外部連携 | 各連携の正常系と合意した異常系の試験が完了している |
| 受入・移行 | Must要件の受入条件を満たし、移行・運用手順が承認されている |

- ISSUE-015: 移行対象となる未処理申請の件数と品質
