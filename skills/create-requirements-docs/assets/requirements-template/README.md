条件付き・任意文書の主な作成条件は次のとおり。

- ターゲットとペルソナ: 対象顧客や典型的利用者像を、UI・UXや優先順位の判断に利用する場合。
- 業務フロー Before／After: 既存業務を変更し、現行と将来の手順、役割、受け渡し、業務ルールの差分を合意する場合。
- 関連システムとシステム連携: 外部システムとの接続またはデータ授受がある場合。
- 競合調査と機能候補: 競合・代替手段の調査を差別化、機能の採否、優先順位の判断に用いる場合。
- 共通付録: 用語、仮定・制約、決定、未確定事項を本文外で一元管理する必要がある場合。
- 開発計画: 複数フェーズ、依存関係、段階的な完了条件を管理する場合。
- 技術設計: 合意した要件と制約を、具体的な構成や実装方式へ落とし込む場合。`design/` として要件定義から分離する。

# 経費精算システム 要件定義

## 文書の目的

本書群は、経費精算システムの開発範囲、業務要求、システム要件、
品質条件および受入条件について、業務部門と開発チームが合意するために作成する。

## 対象プロジェクト
