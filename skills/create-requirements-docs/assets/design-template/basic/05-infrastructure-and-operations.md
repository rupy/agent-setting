# インフラ・運用設計

## 1. 文書の目的

システムの環境、ネットワーク、配備、監視、バックアップ、定常運用と障害対応を定義する。

## 2. 入力となる要件・制約

NFR-001、NFR-002、NFR-007、非機能要件11節、13節、CON-002を入力とする。

## 3. 環境構成

開発、検証、本番を分離する。本番と検証は同じ構成要素を使用し、規模とデータだけを分ける。

## 4. ネットワークとセキュリティ

Web入口だけを社内許可経路から到達可能にする。API、データストア、証憑ストレージは非公開ネットワークに配置する。

## 5. ビルド・デプロイ・リリース

版管理されたソースから自動ビルドし、検証環境の試験と承認後に同じ成果物を本番へ配備する。失敗時は直前版へ戻す。

## 6. 監視・ログ・通知

死活、応答時間、エラー率、ジョブ失敗、外部連携失敗、保存容量を監視する。重大障害は運用責任者へ30分以内に通知する。

## 7. バックアップと復旧

申請データと証憑を毎日バックアップする。NFR-007のRPO 24時間、RTO 8時間を年2回の復元試験で確認する。

## 8. 定常運用と障害対応

平日は監視結果と失敗ジョブを確認する。障害時は影響範囲、開始時刻、暫定対応を記録し、復旧後に原因と再発防止策を残す。

## 9. 設計判断

認証はCON-002に従い社内基盤を利用する。監視サービスの選定理由はDEC-003へ記録する。
