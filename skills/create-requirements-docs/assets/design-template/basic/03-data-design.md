# データ設計

## 1. この文書で決めること
経費精算システムで管理する主要データの論理構造、関係、生成・更新・保存、品質とアクセスの方針を定義する。DR-001、FR-001からFR-004、非機能要件のプライバシーを入力とする。

## 2. 主要データと関係
| データ | 識別子 | 主な関係 | 正本 | 関連要件 |
|---|---|---|---|---|
| 申請 | 申請ID | 一つ以上の経費明細と複数の履歴を持つ | 経費精算システム | DR-001、FR-001 |
| 経費明細 | 明細ID | 一つの申請に属し、証憑を持つ | 経費精算システム | DR-001 |
| 証憑 | 証憑ID | 一つの経費明細に属する | 証憑ストレージ | DR-001 |
| 利用者・組織 | 従業員ID・組織ID | 利用者は一つの組織に所属する | 人事システム | IF-002 |

## 3. データの生成・更新・保存
申請は下書きとして生成し、提出、承認、会計連携を経て保存期間満了後に削除する。申請と履歴は業務データストア、証憑本体は証憑ストレージへ保存する。利用者と組織は人事システムから取り込む。

## 4. データの品質とアクセス
申請金額と明細合計を一致させ、無効な経費区分を拒否する。申請者は自分の申請、承認者は担当申請、経理・監査担当者は権限範囲の申請だけを参照できる。

## 5. 設計上の判断と未確定事項
- 設計判断: 申請を整合性管理の単位とし、申請更新時に明細と履歴をまとめて扱う。
- ISSUE-036: 退職者の表示名を保持する期間。
- ISSUE-037: 証憑と申請データを同一時点へ復元する方法。
