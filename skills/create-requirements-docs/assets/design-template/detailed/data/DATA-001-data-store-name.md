# DATA-001 経費申請データベース

## 1. この文書で決めること
申請・承認データの整合性や検索性能へ影響する物理構造、制約、索引、スキーマ変更方法を定義する。

## 2. 構造と関係
`expense_application` は申請ID、申請者ID、状態、合計金額、作成日時、更新日時を持つ。`expense_item` は明細IDと申請IDを持ち、一つの申請に複数の明細を関連付ける。

## 3. 制約と整合性
申請者IDと状態は必須とし、明細は必ず存在する申請へ関連付ける。申請と明細の登録、提出時の状態更新は同一トランザクションで行う。

## 4. 検索と性能
申請者別一覧のため申請者IDと更新日時、承認待ち一覧のため状態と更新日時に複合インデックスを作成する。想定件数はデータ要件DR-002を参照する。

## 5. 履歴・削除・スキーマ変更
提出済み申請は物理削除せず、変更履歴を監査記録へ残す。スキーマ変更は前方互換性を保つ段階的なマイグレーションとし、破壊的変更は二回のリリースに分ける。

## 6. 設計上の判断と未確定事項
- 設計判断: 申請と明細を別テーブルに分け、データベース制約で関係を保証する。
- ISSUE-050: 承認済み申請のパーティション分割が必要になる件数を性能試験で確認する。
