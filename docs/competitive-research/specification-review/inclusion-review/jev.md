調査記録: [jev-research.md](../jev-research.md)

## 調査で確認した内容

- 対象と方法: Jevは文脈に対する選択肢、確率、段階評価を返す。公式資料の設計指針を確認し、仕様とコードの照合への活用を検討した。
- 参考になる点: 要件、根拠となるコード、検査質問、合否条件を対応付け、複数の判断をコードで組み合わせる。
- 適用上の注意: 今回期待する主な利点はコスト削減である。応答の速さと型付きの出力は今回の用途では決め手にならず、導入はいったん見送る。費用や精度は実測していない。

## スキルに含める項目リスト

| 項目 | 判断 | 理由と入れる内容 |
| --- | --- | --- |
| 要件と受入条件を対応付ける | 既存で対応 | 現行テンプレートの要件IDとトレーサビリティを使う。同じ情報を管理する文書を別に増やさない。 |
| 要件ごとに検査質問と対象コードを結び付ける | 追加候補 | 実装の照合を行う場合に、どの要求を何で確認したか追えるようにする。 |
| 一つの質問で一つのまとまった判断を扱う | 条件付き | 複数の要求を一つの質問に詰め込み、どの要求を満たしていないのか分からなくなることを避ける。文脈や必要条件は削らない。 |
| 独立した質問を同じ入力にまとめる | 条件付き | 評価手順の設計として参考にする。前の回答が必要な質問は別の処理へ分ける。Jevの導入は前提としない。 |
| モデルへ渡る情報と検査対象外を確認する | 追加候補 | 必要な条件や根拠が入力に揃っているかを確認し、入力の不足とモデルの判断ミスを分けて扱う。 |

| 不確かな結果を人のレビューにつなぐ | 条件付き | 根拠となる仕様・コードと結果を残す。数値だけでは判断の理由を説明したことにならない。 |
| 今回の評価にJevを導入する | 見送る | 主な利点はコスト削減だが、評価品質を保ち、連携や追加レビューを含めても費用を減らせるかは未確認。応答の速さと型付きの出力は、今回の決め手にならない。 |
| 公開資料の性能値やしきい値をそのまま採用する | 見送る | 対象案件での効果や運用費用を実測した値ではない。モデルの版と入力条件を揃えて確認する。 |
| Jevの判定で実行テストや人の判断を置き換える | 見送る | 入力にない事実や未決の業務要求は確定できない。受入の最終判断と補助的な照合を分ける。 |

## 結論

今回の要件でJevに期待できる主な利点は、**コスト削減**である。応答の速さと型付きの出力の重要度は現状では低いため、導入はいったん見送る。評価手順は通常のLLMを使用する前提で整備する。

要件・対象コード・評価観点を対応付け、渡した情報と検査対象外を記録する方法は、Jevに依存しない改善候補として残す。

この結論は、現時点の要件と公式資料を照らし合わせた判断である。モデル同士を実測で比較し、性能差を確認したものではない。実際の費用削減効果は未確認である。評価の回数や費用が増えた場合、または即時の応答や型付き出力のプログラムへの組み込みが必要になった場合に再検討する。今回、比較実験や既存スキルへの反映は行っていない。
