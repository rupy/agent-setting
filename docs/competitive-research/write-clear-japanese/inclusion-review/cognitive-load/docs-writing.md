# docs-writing の採否検討

調査記録: [cognitive-load-writing-skills-research.md](../../cognitive-load-writing-skills-research.md)  
[照合先: write-clear-japanese](../../../../../skills/write-clear-japanese/SKILL.md)

## 調査で確認した内容

- 対象と方法: 技術文書を読者の作業に応じてチュートリアル、手順、リファレンス、解説に分類し、種類に合う規則だけを適用する。例とリンクの動作も確認する。
- 参考になる点: 文書種別を先に決めることで、作業中の読者に不要な背景説明を読ませたり、学習中の読者に前提なしの操作をさせたりする問題を減らす。
- 適用上の注意: 要件定義・設計文書では、同一ファイルに複数の目的がある場合もある。分類を機械的な分割命令にしない。

## スキルに含める項目リスト

| 項目 | 判断 | 理由と入れる内容 |
| --- | --- | --- |
| 読者の作業に合わせて構成を選ぶ | 条件付き | 手順・解説の構成違いが問題になれば一文を補う。 |
| 例とリンクの動作を確認する | 条件付き | 実行可能な技術文書を作る案件で検証する。 |
| 四分類でファイル分割を強制する | 見送る | 一つの文書に複数の目的がある場合もある。 |

## 結論

この対象から現行スキルへ直ちに追加する項目はない。条件付き・保留の項目は、実文書で不足が確認された場合に再検討する。この判断は調査記録と現行スキルの照合であり、対象スキルを導入して出力品質を比較した結果ではない。
