## 調査で確認した内容

- 対象と方法: 製品文書の手順・概念・リファレンスを区別する。手順には前提、実行内容、期待結果、よくある失敗を記載する。
- 参考になる点: 読者が操作の意味と成功状態を自分で推測する負担を減らす。概念は平易な説明、具体例、正確な用語の順に導入する。
- 適用上の注意: Prisma 固有の構成や名称は移さず、手順の完了確認と前提の置き方を参考にする。

## スキルに含める項目リスト

| 項目 | 判断 | 理由と入れる内容 |
| --- | --- | --- |
| 手順に前提と期待結果を添える | 追加候補 | 現行スキルは操作順を扱うが、成功状態の明示は弱い。 |
| 失敗時の対処を操作の近くに置く | 追加候補 | 手順書で読者が試行錯誤せずに進める。 |
| 製品固有の文書分類を移植する | 見送る | 対象製品と文書構成が異なる。 |

## 結論

現行スキルへの追加候補は「手順に前提と期待結果を添える」「失敗時の対処を操作の近くに置く」。実際の文書で不足が起きる場面を確認し、対象文書に限る短い指針として検討する。この判断は調査記録と現行スキルの照合であり、対象スキルを導入して出力品質を比較した結果ではない。
