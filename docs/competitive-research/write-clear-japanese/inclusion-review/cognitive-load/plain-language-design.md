# plain-language-design の採否検討

調査対象: [plain-language-design](https://github.com/Owl-Listener/inclusive-design-skills/blob/main/cognitive-accessibility/skills/plain-language-design/SKILL.md)  
調査記録: [cognitive-load-writing-skills-research.md](../../cognitive-load-writing-skills-research.md)  
[照合先: write-clear-japanese](../../../../../skills/write-clear-japanese/SKILL.md)

## 調査で確認した内容

- 対象と方法: 認知アクセシビリティを意識した UI 文言・手順・ヘルプの推敲。読者が次に行う操作の曖昧さと、エラー文の説明不足を点検する。
- 参考になる点: 表現を簡単にするだけでなく、指示の行動と主体を特定できるかを見る。変更前・問題・修正文を並べるレビュー形式も使える。
- 適用上の注意: 既出の `plain-language` と重なる。英語の語数・学年水準や「5秒」などは効果が確認された普遍的な閾値として採用しない。

## スキルに含める項目リスト

| 項目 | 判断 | 理由と入れる内容 |
| --- | --- | --- |
| UI 文言の主体と次の操作を明確にする | 条件付き | 画面内の案内文を作る場合に有用。 |
| エラー文に原因と対処を示す | 別スキル向け | UI 状態と操作の検証が必要。 |
| 語数・学年水準・秒数を普遍的な閾値にする | 見送る | 対象読者と媒体で変わる。 |

## 結論

この対象から現行スキルへ直ちに追加する項目はない。条件付き・保留の項目は、実文書で不足が確認された場合に再検討する。この判断は調査記録と現行スキルの照合であり、対象スキルを導入して出力品質を比較した結果ではない。
