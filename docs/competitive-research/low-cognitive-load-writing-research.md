# 読み手の不要な認知負荷を減らすライティング

調査日: 2026-09-22

## この文書の目的と範囲

日本語の技術文書、業務文書、案内文、Web コンテンツを、読み手が情報を探し、理解し、使いやすい形にするための調査。Agent Skill やプロンプトの事例は対象外とし、原著論文、公的機関の指針、文書設計の一次資料を中心に確認した。

「認知負荷をなくす」ことは目標にしない。新しい概念を学び、判断するには思考が必要である。ここでは、目的に関係のない探索、記憶、推測、読み直しを減らすことを指す。認知負荷理論は主に学習課題を説明する理論であり、以下のすべての文章規則を直接実証するものではない。[Sweller (1988)](https://onlinelibrary.wiley.com/doi/10.1207/s15516709cog1202_4)、[Mayer & Moreno (2003)](https://carpentries.github.io/instructor-training/files/papers/mayer-reduce-cognitive-load-2003.pdf)

## 調査から分かったこと

### 1. 読者の仕事から内容を選ぶ

最初に「誰が、この文書を使って何を判断・実行するか」を決める。GOV.UK は利用者の必要を行動や課題として記述し、既存の分析や利用者調査で確かめるよう求める。文化庁も、平易に書くだけでは足りず、読み手の欲しい情報が入っていることを重視する。不要な情報を削る前に、必要な情報の欠落を確認する。[GOV.UK の利用者ニーズ](https://guidance.publishing.service.gov.uk/writing-to-gov-uk-standards/plan-manage-content/identify-user-needs/)、[文化庁の解説](https://www.bunka.go.jp/seisaku/bunkashingikai/kokugo/hokoku/pdf/92968501_01.pdf)

技術文書では、学習用のチュートリアル、特定作業の手順、仕様の参照、背景の説明を分けると、読者が現在の目的に不要な説明を処理せずに済む。これは Diátaxis の設計上の提案であり、万能な四分類の実験的証明ではない。[Diátaxis](https://diataxis.fr/start-here/)

### 2. 情報を見つける手掛かりを作る

Web ページでは、多くの読者が最初に走査する。1990年代の Nielsen と Morkes のサイト実験では、簡潔、走査しやすい、誇張しない文章が利用上の成績を上げた。ただし当時のサイトと被験者の結果であり、数値を現代の全サイトに当てはめない。見出しを内容に即して付け、重要な語を先頭に置き、段落を話題ごとに分けることは、今日の [Google の段落ガイド](https://developers.google.com/style/paragraph-structure) や [W3C の指針](https://www.w3.org/WAI/WCAG2/supplemental/objectives/o3-clear-content/) とも一致する。[原研究](https://www.nngroup.com/articles/concise-scannable-and-objective-how-to-write-for-the-web/)

見出しは「概要」「その他」だけでは選択の助けにならない。読者の問いや行動を表す見出しにする。実験では、文章に題名があると記憶や読解時の視線移動が改善した例がある。一方、見出しを増やしすぎると選択肢も増えるため、最適な数を固定できない。読者の作業に合う見出しかを実際に探してもらって確かめる。[題名の実験](https://pubmed.ncbi.nlm.nih.gov/11105527/)、[文書テンプレートのユーザーテスト研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC4596875/)

HTML では、リンク単体で移動先が分かる名前にする。「こちら」「詳しく」は、前後の文から切り離されると判断できない。目次、見出し階層、読みやすい行間も探索と再開を助ける。[デジタル庁のリンクテキスト指針](https://design.digital.go.jp/dads/foundations/link-text/accessibility/)、[デジタル庁のタイポグラフィ指針](https://design.digital.go.jp/dads/foundations/typography/accessibility/)

### 3. 文の解釈を一意に近づける

一文に条件、例外、理由、指示を詰め込むと、読者は関係を保持しながら読み進める必要がある。条件を行動の前に置き、実行順のある手順は番号付きで分ける。指示語が複数の名詞を指し得るときは、対象名を繰り返す。専門語は対象読者に必要なものを残し、初出で短く定義する。[Google の技術文書ガイド](https://developers.google.com/style/highlights)、[W3C の文章指針](https://www.w3.org/WAI/tips/writing/)

日本語では、主語の省略自体を欠陥にしない。誰が行うかを取り違える場面で主体を補う。「短文」「能動態」を機械的な目標にすると、条件や責任主体を落とすことがある。文化庁の指針は、読み手と目的に応じた表現の選択を前提とする。[文化庁「公用文作成の考え方」](https://www.bunka.go.jp/seisaku/bunkashingikai/kokugo/hokoku/93657201.html)

### 4. 論理の橋を読者に作らせない

段落間で話題、対象、原因と結果が変わるなら、その関係を短く明示する。既知の情報だけで補えない飛躍は、接続詞を足すだけでは埋まらない。読者がなぜその結論になるか説明できるだけの根拠や過程を書く。先行知識やワーキングメモリが文章理解に関係する研究があり、低い結束性の文章では読者に推論を多く求める。[読解とワーキングメモリの研究](https://www.frontiersin.org/journals/education/articles/10.3389/feduc.2020.00026/full)、[テキストと図の結束性の研究](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2020.592509/pdf)

ただし、説明を重ねるほどよいわけではない。読者が既に知る概念を毎回定義すると、目的の情報を探しにくくなる。読者の知識水準に合わせて、必要な前提だけを近くに置く。[図と文章の手掛かりのメタ分析](https://www.sciencedirect.com/science/article/pii/S1747938X15000664)

### 5. 例、図、表を本文と結び付ける

抽象的な規則の後に、その規則を使う具体例を置く。例の対象、入力、操作、結果を本文で対応付ける。図と本文の対応を強調する手掛かりを調べたメタ分析は、全体として小から中程度の正の効果を示し、特に事前知識が少ない学習者で効果が大きかった。ただし、主な対象は学習用の図解資料であり、全ての表や装飾画像の追加を支持するものではない。[メタ分析](https://www.sciencedirect.com/science/article/pii/S1747938X15000664)

表は同じ項目を複数対象で比較するときに使う。手順や因果の説明を小さなセルに押し込むと、読者が読む順番を推測しなければならない。アイコンや色は好まれても、理解度が上がるとは限らない。研究参加案内を対象とした無作為化試験では、視覚要素のある版が好まれた一方、知識などの測定値には有意差がなかった。[視覚要素の試験](https://pmc.ncbi.nlm.nih.gov/articles/PMC13124231/)

### 6. 平易さと正確さを両立する

平易な言葉は、情報の欠落や確実性の誇張を意味しない。比較試験では、平易な健康勧告の版が一方の勧告で理解度を改善したが、もう一方では統計的に明確な差がなかった。別の試験では、新しい平易な要約の版で利益・害・証拠の質の理解が高かった。効果は文章の主題、元の品質、提示形式に依存する。[2024年の比較試験](https://pubmed.ncbi.nlm.nih.gov/38008266/)、[2014年の比較試験](https://pubmed.ncbi.nlm.nih.gov/25034199/)

平易な文章を扱う国際規格 [ISO 24495-1:2023](https://www.iso.org/standard/78907.html) は、一般向け文書だけでなく技術文書にも適用可能としている。ただし、公開ページで読めるのは規格の概要であり、本調査は有料の規格本文を確認していない。日本語の実務では、[文化庁・出入国在留管理庁の「やさしい日本語」ガイドライン](https://www.bunka.go.jp/koho_hodo_oshirase/hodohappyo/pdf/92488301_03.pdf) が、元文の一語一句を置き換えるのでなく、伝えるべき内容を選び直すよう求めている。対象読者に合わせた情報選択が先である。

反例もある。知的障害のある成人60人を対象とした試験では、言語の単純化だけによる理解度の有意な改善は確認されなかった。単語や文長の調整だけで、読者の理解を保証しない。[Easy Read の試験](https://pubmed.ncbi.nlm.nih.gov/31652030/)

数値や不確実性を扱う場合は、「効果がある」のような短縮で判断に必要な条件を失わない。誰に、どの条件で、どの程度、何と比べて、どれほど確かかを、用途に応じて残す。[不確実性の表現を比較した試験](https://pubmed.ncbi.nlm.nih.gov/40101228/)

### 7. 見た目も文章理解の一部として確認する

本文の文字サイズ、行間、段落間隔、見出し階層、余白は、現在位置の把握や走査に影響する。デジタル庁デザインシステムは、読み物の本文に十分な行高を推奨し、長い斜体、追いにくい長い行、読みにくい詰まった行間を避けるよう案内している。ただし提示値は用途に応じた設計上の目安であり、全媒体の認知負荷を一つの数値で測った結果ではない。[タイポグラフィ](https://design.digital.go.jp/dads/foundations/typography/)、[アクセシビリティ](https://design.digital.go.jp/dads/foundations/typography/accessibility/)

## 推敲と検証の進め方

1. **課題を決める。** 読者が文書から答えを得る質問や、完了すべき作業を3～5個挙げる。これは検査用の目安で、文書の規模に合わせて増減する。
2. **探索を試す。** 対象読者に、見出しとリンクを使って答えの位置を探してもらう。見つけるまでの時間、誤った場所、戻った箇所を記録する。
3. **理解を試す。** 文章を閉じて、重要な条件、例外、次の行動を自分の言葉で説明してもらう。短く読めたかだけで判断しない。
4. **実行を試す。** 手順書なら実際のタスクを行い、完了率、ミス、問い合わせ、やり直しを確認する。高リスクな文書では、専門家による正確性の確認も加える。
5. **改訂を比較する。** 元の版と改訂版で同じ課題を行い、対象者の知識や環境を揃えて比較する。好みと正答率を分けて記録する。

この評価方法は、利用者の課題から内容を設計する [GOV.UK の指針](https://guidance.publishing.service.gov.uk/writing-to-gov-uk-standards/plan-manage-content/identify-user-needs/) と、見出しや構成を実際の探索課題で試す [文書テンプレート研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC4596875/) を踏まえた提案である。

## 避けたい単純化

- **短ければ読みやすい**: 条件、責任主体、根拠を落とした短文は、読者の推測を増やす。
- **見出しが多ければ探しやすい**: 選択肢や重複が増える。検索語と見出しの対応を読者の課題で確認する。
- **専門語はすべて難しい**: 対象読者に共通の正確な語は残す。必要なときだけ説明する。
- **図や色を足せば理解が上がる**: 本文との対応と実際の理解度を確かめる。
- **文長や readability スコアが合格なら十分**: 構成、因果、事実、読み手の行動は別に検証する。
- **認知負荷理論から一律の文字数が決まる**: 文書、読者、目的ごとに必要な情報量は変わる。
